# Инфраструктура: деплой, вебхук, диагностика

Короткая сводка — в `AGENTS.md`, раздел «Инфраструктура и деплой».
Здесь процедуры, которые нужны редко.

## Как устроен деплой

Пуш в `main` → GitHub отправляет вебхук в Coolify → Coolify собирает образ
в Docker и поднимает контейнер. Сборка занимает около 9 минут.

Панель Coolify: `http://201.24.124.88:8000`
Приложение: проект `jbtt4azgggy9bdp6kn1ctiwx` → окружение
`sapy28qdxshv1pxhkl1w5bip` → приложение `ss8zuddnbz5xm6vib1ndqnaa`
(этот же UUID лежит в `.env.local` как `COOLIFY_APP_UUID`).

## Как проверить, что деплой прошёл

Только через интерфейс: приложение → **Deployment Logs**. Там видно статус
(Success / Failed), источник (Webhook / Manual), SHA коммита и длительность.

Через API проверить нельзя, это проверено 2.09.2026:

- `/api/v1/applications/{uuid}` в поле `git_commit_sha` всегда отдаёт строку
  `"HEAD"`, а не хэш задеплоенного коммита;
- `/api/v1/deployments` возвращает пустой массив даже после успешной сборки —
  видимо, показывает только активную очередь;
- `npm run coolify -- status` показывает `running:unknown` независимо от того,
  что задеплоено;
- `npm run coolify -- logs` отдаёт логи работающего контейнера (runtime),
  а не лог сборки.

## Если пуш не запускает деплой

Симптом: коммит в `main` есть, а в Deployment Logs новой записи нет.

1. GitHub → репозиторий `Dzeyt/kamvek` → **Settings** → **Webhooks**.
   Должен быть один вебхук на адрес
   `http://<IP-сервера>:8000/webhooks/source/github/events/manual`.
2. Если IP в адресе не совпадает с текущим IP сервера — нажать **Edit**
   и поправить. IP сервера видно в панели Timeweb, раздел IP-адреса.
3. Кликнуть на вебхук → прокрутить до **Recent Deliveries** → открыть
   верхнюю (последнюю) доставку → кнопка **Redeliver** справа сверху.
4. Обновить страницу: зелёная галочка — дошло, красный крестик с текстом
   «failed to connect to host» — соединения нет вовсе.

История: 2.09.2026 деплой не запускался, потому что в вебхуке остался старый
IP `85.239.38.133`, а сервер уже работал на `201.24.124.88`. После правки
адреса первая доставка всё равно упала, но **Redeliver** прошёл успешно —
то есть это была временная сетевая проблема, а не файрвол. Файрвол в панели
Timeweb на тот момент был пуст (ни одной группы правил), DDoS-защита выключена.

Если Redeliver не помогает, проверять в таком порядке:

- открыт ли порт 8000 снаружи — внешним чекером (`https://check-host.net/check-tcp`),
  а не из своего браузера: браузер может держать старое соединение;
- файрвол в панели Timeweb → сервер → Firewall;
- `ufw status verbose` внутри сервера — через вкладку **Terminal** в Coolify.

У панели Coolify нет своего домена (`wildcard_domain` пустой), поэтому вебхук
идёт на голый `IP:8000` и ломается при каждой смене IP. Если это надоест —
задача на будущее: прикрутить панели домен с HTTPS и перевести вебхук на него.

## Домен сайта

В Coolify → приложение → **Domains** у `https://kamen-veka.ru` может стоять
статус «DNS pending». Это собственная проверка Coolify (сверяет IP домена
с IP сервера), она не влияет на работу сайта. Сайт при этом отвечает 200.

## Переменные окружения

Задаются в Coolify → приложение → **Environment Variables**.
Посмотреть из терминала: `npm run coolify -- env` (только чтение).
Список всех переменных с пояснениями — в `.env.example`.
