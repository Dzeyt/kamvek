# КАМВЕК — контекст проекта

Сайт компании «Камень Века» (ООО «Камвек») — изготовление изделий из натурального камня
на заказ. Продвижение под Яндекс, регионы: Москва, МО, Раменское, Бронницы, Коломна, Рязань.

**Продакшн:** https://kamen-veka.ru
**Владелец проекта:** Мухаммад Дзэйт (разработка + SEO, работает один).
Отвечать по-русски.

## Стек

Next.js 16.1.1 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · framer-motion
Хостинг: Coolify на VPS Timeweb (регион Москва/СПб).

```
npm run dev · build · lint
npm run images:optimize      # сжатие изображений (sharp)
npm run portfolio:generate   # генерация src/data/portfolio.ts из файлов
npm run metrika              # статистика из Метрики за 30 дней (или: -- 7)
npm run webmaster            # индексация, ошибки и запросы из Вебмастера
npm run coolify -- apps      # деплой: apps | status | env | logs [N] | deploy
```

Секреты для этих скриптов лежат в `.env.local` (в гит не попадает).
Полный список переменных с пояснениями — в `.env.example`.

## Структура

- `src/app/` — роуты App Router. Существует **7 страниц**: `/`, `/uslugi`,
  `/katalog-kamnya`, `/portfolio`, `/o-kompanii`, `/kontakty`,
  `/politika-konfidencialnosti`. Отдельных страниц под услуги (`/uslugi/stoleshnitsy`
  и т.п.) **пока нет** — это следующая задача.
- `src/data/` — единственный источник данных: `services.ts` (10 услуг),
  `stones.ts`, `portfolio.ts`, `portfolio-order.ts`, `contacts.ts`.
  Контакты и телефоны править только здесь, не в компонентах.
- `src/components/` — общие компоненты.
- Страницы устроены как серверный `page.tsx` (метаданные) + клиентский
  `*Client.tsx` (анимации, интерактив). Сохранять эту схему.

## Заявки с сайта

`src/app/api/lead/route.ts` — приём заявок, лимит 3 запроса в минуту с IP.
Переменные задаются в Coolify: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `LEAD_EMAIL_TO`.

Открытые проблемы:
1. Роут отдаёт 500, если не заданы переменные Telegram, — даже когда email настроен.
   Стоит сделать Telegram опциональным.
2. Honeypot: сервер проверяет поле `website`, но клиент его не отправляет.

Нестабильная доставка в Telegram решена 2.09.2026 через `fetchWithRetry`
(3 попытки, таймаут 6с): после деплоя `41bcf71` дошли 6 тестовых заявок из 6.

## Инфраструктура и деплой

- Пуш в `main` → вебхук GitHub → автодеплой на Coolify.
  Панель: `http://201.24.124.88:8000` (домена и HTTPS у панели нет).
- Факт деплоя смотреть **только во вкладке Deployment Logs** в Coolify.
  API врёт: `git_commit_sha` всегда отдаёт строку `"HEAD"`, а
  `/api/v1/deployments` возвращает пустой массив даже после успешной сборки.
- `npm run coolify -- logs` — логи работающего контейнера, а не лог сборки.
- При смене IP сервера адрес вебхука в GitHub правится руками.
  Процедура и диагностика — `docs/INFRA.md`.

## Правила

### Git — пуш в main уходит в прод

- `git push` — только после явного подтверждения. Локальный коммит — свободно.
- Перед пушем в `main`: `npm run lint` и `npm run build`. Сборка идёт в Docker
  и раньше падала на том, что локально проходило (коммит `5eefcbc`).
- Перед коммитом показать `git status --short`, не делать `git add -A` вслепую.
- Никогда: `push --force`, `reset --hard`, `checkout .`, `clean -fd`, `rebase`,
  `amend` уже отправленного. Незакоммиченные правки владельца — не наши.
- Не коммитить: `.env.local`, `otchet*`, `.DS_Store`, `tsconfig.tsbuildinfo`.

### Секреты

- Значения из `.env.local` в ответ не печатать — только имена переменных
  и «задана / не задана». Сам файл не изменять.
- Не просить присылать токены в чат.

### Coolify (токен с правами Root)

- `apps`, `status`, `env`, `logs` только читают — выполнять сразу.
- `deploy` и всё, что меняет состояние (переменные, приложение, сервис) —
  только после явного подтверждения на этот конкретный шаг.
- Команда вернула ошибку — показать точный вывод и остановиться,
  не «исправлять» повторными попытками на проде.

### Код

- Не ставить пакеты и не менять версии Next / React / Tailwind без запроса.
- Скрипты к API Яндекса и Coolify — через `scripts/lib/load-env.mjs`
  (`loadEnv`, `preferIPv4`, `fetchRetry`). Node по умолчанию идёт в IPv6,
  на российских сетях это даёт ECONNRESET ещё до установки TLS.
- Тестовые заявки на прод — с пометкой «тест» и не больше пары за раз:
  они уходят на рабочую почту.

### Где что записывать

- План и статусы задач — `docs/ROADMAP.md`.
- Факты об инфраструктуре — этот файл; процедуры — `docs/INFRA.md`.
- Тексты для клиента и семантическое ядро — `src/app/otchet_final.md`.
- Новых `.md` без запроса не создавать.

### Экономия контекста

- Не читать `node_modules`, `.next`, `package-lock.json`.
- Если ответ есть в этом файле — отвечать без чтения кода.
- Не пересказывать содержимое файлов, которые владелец видит сам.
- Не запускать `build` ради проверки правки, не влияющей на сборку.

### Отчёты и факты

- Не заявлять как выполненное то, что не подтверждено кодом, выводом команды
  или скриншотом из Вебмастера / Метрики.
- Тексты для клиента — по-русски, без канцелярита и громких обещаний.

### Задачи во внешних сервисах (Яндекс Бизнес, 2ГИС, Авито, Вебмастер)

Владелец делает их руками в браузере, агент действовать там не может.
Как готовить такие инструкции — `docs/ROADMAP.md`, Этап 3.
Главное: интерфейсы меняются, не уверен в пути — просить скриншот,
а не сочинять (в Coolify вкладки Configuration / Deployments уже переименованы).
